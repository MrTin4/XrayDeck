# 使用指南

## 使用

解压便携包，运行 `xray-deck.exe`。正常使用不需要管理员权限。

同一 Windows 会话只启动一个桌面实例。再次运行工具时，新进程会通知已有实例并立即退出；已有窗口会在约一秒内恢复到前台，包括最小化和隐藏到托盘的情况。首次启动尚未创建窗口时也会保留唤起请求。退出程序后可正常重新启动；命令行诊断和升级提权辅助进程不受桌面单例检测限制。

1. 主页面展示版本、更新状态和出站列表。点击“刷新出站”使用已保存的 API 地址读取运行时出站，默认地址为 `127.0.0.1:8080`。
2. 出站默认按观测延迟从小到大排列。点击“观测延迟”表头切换延迟从小到大 / 从大到小，点击“观测时间”表头切换时间从早到晚 / 从晚到早；箭头标记当前排序，切换到另一列时从升序开始。无有效时间的节点在时间排序末尾；延迟排序中不可达、缺失或负延迟的节点在两种方向下均置后，相同值保持原顺序。排序只调整展示，刷新不触发测速。
3. 点击右上角“设置”进入独立页面，配置 API 地址并“保存并测试连接”；填写 Windows 服务名、WinSW XML 和 `xray.exe` 完整路径后保存，将自动查询版本并校验关联，下次启动也会自动检查。界面仅显示运行版本，升级仍需完整关联校验通过，失败原因在设置页展示。可点击“校验关联与版本”重试。仅支持服务程序同名 XML。“返回主页”保留输入草稿及当前结果。
4. 每次启动会自动执行一次内核官方更新检测，结果显示在顶部；也可点击“检查官方更新”手动重查。自动检测沿用已保存的更新渠道，仅检查版本，升级仍需手动确认。更新渠道和升级操作位于设置页，默认仅正式版，可切换为包含预发布版。关联成功且目标版本更高时可升级。
5. 升级前展示重启提示。下载和摘要校验完成后请求 UAC，由独立辅助进程复核服务、官方发布和校验值，再停止服务、备份、替换、启动并检查 API；失败时尝试回滚。
6. 在设置页的“出站自动刷新”中开启功能并输入间隔（5–86400 整数秒），点击“保存刷新设置”。保存后从新的间隔开始计时，重启应用后恢复。自动刷新仅在主页面执行；设置页、后台忙碌或升级确认期间跳过该次刷新，不积压请求。手动刷新重新计时，刷新过程中保留现有列表；读取失败显示错误，保留上次结果及读取时间，并按间隔继续尝试。
7. 自动刷新倒计时显示在“刷新出站”按钮内，每秒更新，计时来自实际刷新计划。数字固定预留两位宽度，“秒”字位置保持不变；超过 99 秒时显示“99+秒”，进入最后 99 秒后显示实际秒数。手动刷新后重新计时，刷新期间保持“刷新出站”文字及倒计时区域可见，避免按钮内容和宽度切换；其他后台任务忙碌或等待升级确认时隐藏倒计时，悬停按钮可查看完整状态；关闭自动刷新后只显示刷新按钮。倒计时不代表核心重新测速。
8. 启动时先显示“启动忙碌”，等待核心版本和服务关联检查结束；如果开启了自动刷新，就绪后立即读取一次出站，不等待完整间隔，并从本次读取重新计时。未配置本地核心路径或本地检查失败也不阻止读取 API；关闭自动刷新时不自动读取出站。首次出站读取结束后（成功或失败）自动检查一次内核更新；未开启出站自动刷新时，本地检查结束后直接检查更新。配置加载失败时保留错误、不自动读取出站，更新检测使用默认渠道。
9. 出站标题区域显示“出站节点”和连接状态/数量/最近读取时间，参照顶部应用标题与运行版本按文字基线对齐；自动刷新倒计时位于右侧刷新按钮内。顶部应用标题后显示运行版本和更新检查进度/结果/错误，旁边的“检查更新”以超链接样式触发原有检查；工具版本位于右侧设置按钮旁。长内容可换行，列表占余下空间。各类状态独立保留，自动刷新不会覆盖检查更新的结果；设置保存反馈与本地诊断在设置页内展示。

下载采用系统网络设置，没有独立代理配置。设置、日志、升级缓存和备份位于 `%APPDATA%\XrayDeck\`。关闭窗口会隐藏到系统托盘，自动刷新和后台操作继续运行。点击托盘图标，或右键选择“打开 XrayDeck”可恢复窗口；右键选择“退出”才会退出面板，不停止 Xray。服务替换等关键升级阶段会等操作完成再退出，等待期间窗口会显示进度。Windows 资源管理器重启后会尝试恢复托盘图标；若恢复失败则显示窗口，避免无法找回面板。托盘初始化失败会写入日志，此时关闭窗口仍按正常退出处理。

设置文件格式：

```json
{
  "api_address": "127.0.0.1:8080",
  "service_name": "winsw-xray",
  "winsw_config": "D:\\Apps\\xray\\winsw-xray.xml",
  "xray_path": "D:\\Apps\\xray\\xray.exe",
  "include_prerelease": false,
  "auto_refresh": false,
  "refresh_interval_secs": 30
}
```

## 能力边界

- 节点仅从 `HandlerService.ListOutbounds` 获取，凭据不进入界面模型或日志。未知协议保留 tag，无法解析的地址显示未知。
- Reflection 未开启时无法完整列举服务；改用节点、路由列表、系统统计和观测的只读方法探测能力，并明确提示限制。
- 当前标准 API 不提供完整的非负载均衡手动分组，因此没有分组和切换入口。
- 没有主动测速 API。若 Observatory 可用，仅展示核心已有观测结果和时间，不能把刷新当成发起测速；未确认 URL 时不标为 HTTPS 延迟。
- 本机使用的 Xray 26.10.10 Burst Observatory 将 `last_try_time` 和 `last_seen_time` 固定返回 0（[官方实现](https://github.com/XTLS/Xray-core/blob/v26.10.10/app/observatory/burst/burstobserver.go)），所以不存在可读取的真实探测时间。工具识别 `health_ping` 字段后显示“核心未提供”及诊断说明，不用客户端读取时间替代。普通 Observatory 返回有效时间时正常显示、排序；未返回观测记录的节点显示“—”。
- 如提示观测 API 未注册，请参考 [开启观测 API](enable-observatory.md)，在现有 `api.services` 中追加 `ObservatoryService`，并检查观测模块是否已配置。
- 版本查询使用 `xray.exe --version`，不读取启动日志。服务、API 进程和核心路径关联通过后显示关联核心文件的命令版本；可直接查询进程路径时先核验该路径。权限不足时使用已校验的 WinSW 配置关联路径，并在设置页明确注明来源及实际映像路径未直接确认；该方法读取的是核心文件命令输出，不读取进程内存版本。升级时仍须在提权后强制复核实际进程路径，复核失败不会停服。
- 升级只支持本机回环 API、WinSW 同名 XML 和 Windows x64 核心，不支持远程升级或改写路由。

## 升级恢复

每次升级的备份位于 `%APPDATA%\XrayDeck\updates\<操作编号>\xray.previous.exe`，结果记录在同目录的 `result.txt`。升级辅助进程不依赖主窗口继续存活。若系统重启等原因导致辅助进程异常终止，先检查服务、核心和备份；确认没有升级进程运行后，才可以清理遗留的 `upgrade.lock`。回滚失败时保留备份，不自动删除。


## 节点累计流量与选中状态

流量列在同一列中单行显示“↑ 上行 / ↓ 下行”（分别为发往远端与从远端接收），自动使用 B / KiB / MiB 等单位。数据来自 StatsService/QueryStats，自核心启动或计数器上次重置起累计；面板不会重置计数器。缺少某方向计数时显示 —，真实零值显示 0 B。

需在核心启用 `StatsService`、`stats: {}`，并在 `policy.system` 启用 `statsOutboundUplink` 和 `statsOutboundDownlink`，保留原有配置后重启核心。

无需配置负载均衡器 tag。面板根据本机 API 监听进程自动关联 WinSW 服务，读取其启动配置中的全部 `routing.balancers`，按 selector 前缀匹配运行时出站并合并去重，包含配置的回退节点和 API 返回的手动覆盖目标。支持 `-c` / `-config`（包括 `=路径`）、多个配置文件、`-confdir` 目录和默认工作目录配置；支持 JSON / JSONC 注释，按核心规则以后出现的 routing 块覆盖前面的 routing 块。无需额外设置即可查询所有发现的负载均衡器，读取选中状态仍需核心启用 `RoutingService`。

自动发现适用于本机 WinSW 服务；普通用户无法读取进程命令行时，使用对应服务的 WinSW XML 启动参数。远程 API、配置不可读、非 JSON / JSONC、通过进程环境变量指定且无法定位的配置等情况会明确提示并显示全部出站，避免误隐藏节点。配置文件编辑尚未重启或通过 API 动态修改路由时，磁盘配置与运行时可能不一致，节点范围以发现的启动配置为依据，选中状态来自实时 API。

选中节点使用“●”标记和彩色背景，始终排在其它节点前面；选中组和未选中组各自按当前延迟／时间规则排序。多目标策略会标记核心返回的全部目标，这表示策略目标集合，不代表某条连接最后使用的节点。策略不支持查询、没有目标或接口失败时会显示提示，不根据延迟猜测选中状态。核心重启、目标变化与流量变化会在下一次手动或自动刷新时更新。
